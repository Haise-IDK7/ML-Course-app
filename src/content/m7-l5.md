PyTorch es la librería de deep learning más usada en investigación y, cada vez más, en producción. Hace tres cosas por ti: opera con tensores en CPU o GPU, calcula gradientes automáticamente y ofrece capas y optimizadores ya construidos. Todo lo que escribiste a mano en la lección 6.6 se reduce a unas pocas llamadas.

## Las cuatro piezas

**1. Tensores.** `torch.Tensor` es como un arreglo de NumPy, con dos añadidos: puede vivir en la GPU y puede recordar cómo se calculó.

```python
import torch
x = torch.tensor([[1.0, 2.0], [3.0, 4.0]])
print(x.shape, x.dtype)          # torch.Size([2, 2]) torch.float32
y = x @ x.T + 1                  # mismas operaciones que en NumPy
```

**2. Autograd.** Si un tensor tiene `requires_grad=True`, PyTorch registra las operaciones que lo usan. Al llamar a `.backward()` sobre un escalar, recorre ese grafo hacia atrás y deja el gradiente en `.grad`.

```python
w = torch.tensor(1.5, requires_grad=True)
L = (w * 2.0 - 5.0) ** 2
L.backward()
print(w.grad)                    # tensor(-8.)  -> el ejemplo de la lección 1.2
```

**3. Módulos.** Una red se define como una clase que hereda de `nn.Module`: en `__init__` se crean las capas y en `forward` se dice cómo se conectan. Para redes sencillas basta `nn.Sequential`.

**4. Optimizadores.** Reciben los parámetros del modelo y los actualizan con `.step()`.

## El bucle de entrenamiento

Son siempre los mismos cinco pasos. Apréndetelos de memoria:

```python
for xb, yb in cargador:              # recorre los datos por lotes
    pred = modelo(xb)                # 1. pasada hacia delante
    perdida = perdida_fn(pred, yb)   # 2. calcular la pérdida
    optimizador.zero_grad()          # 3. borrar gradientes anteriores
    perdida.backward()               # 4. retropropagación
    optimizador.step()               # 5. actualizar los pesos
```

::: ojo Los tres errores más frecuentes
1. **Olvidar `zero_grad()`.** PyTorch **acumula** los gradientes; si no los borras, cada paso usa la suma de todos los anteriores.
2. **Poner softmax antes de `CrossEntropyLoss`.** Esa pérdida ya la incluye; espera logits.
3. **No cambiar de modo.** `modelo.train()` al entrenar y `modelo.eval()` más `torch.no_grad()` al evaluar; si no, dropout y BatchNorm se comportan mal y se gasta memoria guardando el grafo.
:::

## Derivadas respecto a la entrada

Para las PINN necesitarás algo que el bucle anterior no usa: derivar la salida de la red respecto a su **entrada**, y conservar el grafo para poder derivar otra vez.

```python
t = torch.linspace(0, 1, 5).view(-1, 1).requires_grad_(True)
u = torch.sin(3 * t)
du = torch.autograd.grad(u, t, torch.ones_like(u), create_graph=True)[0]    # 3 cos(3t)
d2u = torch.autograd.grad(du, t, torch.ones_like(du), create_graph=True)[0] # -9 sin(3t)
```

`create_graph=True` le dice a PyTorch que la derivada también forma parte del grafo, de modo que una pérdida construida con `du` y `d2u` se puede retropropagar hasta los pesos. Es la línea que hace posible una PINN.

::: resumen
- Tensores + autograd + `nn.Module` + optimizador: las cuatro piezas de PyTorch.
- El bucle: forward, pérdida, `zero_grad`, `backward`, `step`.
- `CrossEntropyLoss` recibe logits; usa `train()`/`eval()` y `no_grad()` correctamente.
- `torch.autograd.grad(..., create_graph=True)` da derivadas respecto a la entrada que a su vez se pueden derivar: la base de las PINN.
:::
